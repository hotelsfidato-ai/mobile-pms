# Decisions — Fidato Mobile

Every decision for the app, as the owner made it. **Numbered M-1, M-2 …** so they can never clash
with the PMS's own D-numbers (the clash of 14 Oct: this branch wrote the plan as "D27-322", a number
the PMS had already used). Add a row before you act on a decision; never re-word an old one.

| # | What | The owner decided |

| M-1 | The app's plan (14 Oct; recorded on this branch as "D27-322", written first as D27-321) | **Every role, one slice at a time**, each slice one role with 2-3 screens, shown running before the next starts; the order: the owner's figures (chosen first), housekeeping, the restaurant waiter, reception. **Android and iOS from day one, one Expo code base**, tried in Expo Go; an iPhone install needs an Apple account and a Mac, or Expo's cloud build (code leaves the machine: the owner's explicit yes). **Offline follows the web's rules** (`src/lib/offline.ts`): only the writes the web holds are queued, in order, with the same idempotency key; settlements are refused offline. **Same Firebase accounts and roles; the API decides rights.** **Only the new app** (the web is not changed for phones now). Versions approved: Expo SDK 57 (expo ~57.0.28), React Native 0.86.3, React 19.2.3; safe-area-context ~5.7.0 and the web preview (react-native-web ^0.21.2, react-dom 19.2.3, @expo/metro-runtime ~57.0.16). Real sign-in later, in its own slice. Housekeeping only after the owner has seen slice 1 on the phone |

| M-3 | The native rebuild and how it is run (15 Oct) | **Rebuild the PMS natively for phones with React Native + Expo, as real installed apps** (not two apps in Kotlin and Swift). **Every role, the phone-suited work first**: all 33 services over time, ordered by how much they are used away from a desk; heavy desk set-up screens last or kept on the web (decided per item). **The production route is planned now and decided after slice 2** (Expo cloud builds vs building on this PC; store accounts). **Its own chat and its own helpers**, building only in this folder; its own rules, decisions, defects and memory following the PMS's principles (`CLAUDE.md`, `AGENTS.md`, `docs/PLAN.md`) |
